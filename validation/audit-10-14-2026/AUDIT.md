# MRI Drive Maker audit — 10-14-2026

The original tests imported the module directly. They did not launch the application through Windows PowerShell 5.1 `-File`, so they missed the parameter-binding startup error corrected in v0.1.1. Repeated passing simulations did not cover that entry point or the actual Windows storage/copy command.

Two regression cases were run against the old module before the new fixes: the original 48 cases passed, while copying without a setup batch and cancellation before raw-drive preparation failed. The cancelled raw-drive fixture reached the simulated formatter. `before-fixes-linux.txt` records the 48/50 result. No physical drive was touched.

The corrected code permits verified copying with a blank `SetupBatch`, checks cancellation before any storage work and again at preparation boundaries, validates required source boot files before erasure, and resolves a fresh physical storage object before destructive operations. Replacement identity and non-USB regression fixtures prove that an old displayed disk number does not authorize an erase. Source disks and the automation data disk are protected; nonempty unknown contents still block both copy and preparation.

The package uses one top-level launcher, `START-MRI-DRIVE-MAKER.cmd`. Supporting source is under `App/`; legacy scripts are non-executable text under `Developer/`. ISO mounting is read-only and owned mounts/caches are cleaned up after jobs stop. ZIPs and extracted folders are accepted. Direct-copy recipes do not run a batch or allow mutable-file exceptions. Previous optional batch recipes remain supported.

The Windows ISO/VHD smoke test is separate from the simulated suite. It creates a tiny ISO with non-bootable fixture files and its own unique file-backed VHD; only USB classification for the copy fixture is simulated. Storage commands, FAT32 paths, copying, process handling, hashes, and flush operations are real. A destructive guard check must reject the VHD because it is not USB. An initial Windows run found a real Robocopy exit-16 failure that simulations had hidden; its log showed error 53 on the GUID destination. The copy backend was replaced with a contained Windows file-copy worker that writes through the same pinned volume GUID. A managed directory-creation attempt also failed on that path. Native Unicode CreateDirectoryW and CopyFileW resolved both issues; all eight storage checks passed on the recorded runtime revision. Diagnosis and results are in the validation report.

A READY result establishes file verification and accepted write flushing. It does not establish a bootable MRI image, Secure Boot support, legacy BIOS boot code, or exact equivalence with BDE-to-USB. The proprietary image and utility, a physical USB, and firmware testing are unavailable here. Windows CI uses Windows Server 2025, not a Windows 10/11 store workstation. These limits are explicit in the user guide.
